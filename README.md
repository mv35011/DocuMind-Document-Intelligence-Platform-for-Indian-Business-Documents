## Overview

**DocuMind** is an end-to-end document intelligence platform tailored for Indian financial documents (GST tax invoices, bank statements, and retail receipts). 

Uploaded documents pass through a structured pipeline: page rendering, OCR tokenization, visual extraction using a **4-bit QLoRA fine-tuned Qwen2-VL-2B model**, Indian tax validation (including Base-36 GSTIN check digit verification and CGST/SGST/IGST reconciliation), OCR token grounding, and calibrated confidence scoring. High-confidence documents are automatically approved and indexed; uncertain or rule-failing documents are routed to a human review queue. Users can query approved documents in natural language using an AST-guarded Text-to-SQL and RAG agent.

## Supported Document Types

| Document Type | Key | Primary Extraction Target | Hard Business Rule Checks |
|---|---|---|---|
| **GST Tax Invoice** | `gst_invoice` | Supplier, Buyer, GSTINs, Line items, Tax breakdown, Grand total | Base-36 GSTIN checksum, Intra/Inter-state tax consistency, Taxable total == Lines sum |
| **Bank Statement** | `bank_statement` | Account holder, Last 4 digits, Opening/Closing balance, Transactions | Continuous running balance equality, Period reconcile (Opening + Credits - Debits == Closing) |
| **Retail Receipt** | `receipt` | Vendor name, Date, Line items, Subtotal, Tax, Total | Subtotal + Tax <= Total, Positive line totals |

## Key Features

- **Parameter-Efficient Vision Fine-Tuning**: 4-bit NormalFloat (NF4) QLoRA training on `Qwen2-VL-2B-Instruct` requiring only ~6.8 GB VRAM. Runs on free Kaggle T4 GPUs ($0 cost).
- **Domain-Specific Validation Engine**: Pure-Python validation rules for Indian business accounting, including mathematical Base-36 GSTIN check digit verification and continuous bank running balance checks.
- **Visual Grounding & Calibrated Confidence**: Every extracted field is mapped back to OCR token bounding boxes via RapidFuzz. Confidence is calibrated using logistic regression with reliability diagrams and Expected Calibration Error (ECE) reporting.
- **Multi-Tenant Defense-in-Depth**: Hard database Row-Level Security (RLS) on PostgreSQL, server-side tenant filters on Qdrant vector search, and JWT claims enforcement.
- **AST-Guarded Text-to-SQL**: Natural language questions are translated to SQL and strictly guarded by `sqlglot` AST parsing, blocking destructive operations (`DROP`, `DELETE`, `pg_sleep`) with 100% refusal accuracy.
- **Zero-Cost Remote LLM Strategy**: Uses Groq Cloud's free tier (`llama-3.3-70b-versatile`) for zero-cost baseline and agent synthesis.

## Quick Start

### 1. Clone & Configure Environment
```bash
git clone https://github.com/manmohanvishwakarma/DocMind.git
cd DocMind
cp .env.example .env
```

### 2. Run Test Suite
```bash
# Runs all unit tests (GSTIN checksum, normalizers, validation rules, metrics, SQL guard)
python3 tests/run_tests.py
```

### 3. Start Local Microservices (Docker Compose)
```bash
make up
```
This spins up PostgreSQL 16, Redis, MinIO, Qdrant, Prometheus, Grafana, and the FastAPI application.

### 4. Launch Interactive Streamlit UI
```bash
make demo
```
Access the application at `http://localhost:8501`.

## Fine-Tuning & GPU Workflow

1. **Kaggle T4 Fine-Tuning ($0 Cost)**:
   - Open `training/notebooks/train_kaggle.ipynb` on [Kaggle](https://www.kaggle.com/).
   - Enable GPU T4 accelerator and execute the notebook.
   - Download the resulting `documind_qwen2_vl_adapter.zip` and place in `models/adapter/`.

2. **RunPod vLLM Serving ($0.29/hr Spot)**:
   - Spin up an NVIDIA L4 spot instance on RunPod using `scripts/gpu_up.sh`.
   - Launch vLLM with the adapter and execute the concurrency benchmark:
     ```bash
     python3 -m eval.bench_serving --endpoint http://localhost:8000/v1 --concurrencies 1,4,8,16
     ```
   - Spin down the instance using `scripts/gpu_down.sh`.

## Known Limitations

- **Single-Page Focus for Receipts**: Multi-page bank statements currently require page-by-page extraction and transaction list concatenation.
- **Language Scope**: v1 handles English-language Indian documents; regional scripts (Hindi, Tamil, Marathi) are planned for future versions.
- **Handwritten Content**: Handwritten bills are flagged and filtered out during the initial ingest stage.
